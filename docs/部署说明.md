# StageCue 部署与恢复

## 本地独立部署

Docker和Compose v2，Python3生成配置。执行python3 scripts/init-env.py，生成忽略且0600的.env，管理员、数据库用户与root各自随机密码，无固定公开密码。已有配置不重复初始化。

执行docker compose -p stagecue config --quiet，然后docker compose -p stagecue up -d --build --wait。访问http://127.0.0.1:8129/，健康入口/actuator/health。端口被占用用WEB_PORT覆盖，不停止其他项目。

mysql:8.4有健康检查，后端等待数据库，前端等待后端。非root Java和Nginx，只回环暴露前端；数据库数据在mysql-data命名卷。构建使用官方Java21／Maven3.9、Node24.19镜像、公开固定依赖、缓存锁和依赖网络重试；后端执行Spotless及全部测试，前端执行格式、lint、测试和构建，没有跳过测试参数。

## 初始化与升级

Flyway V1身份、V2舞台提示，JPA ddl-auto=validate。空库初始化admin、角色、权限、菜单、部门、类型和参数，业务表为空。已有库不会重置账号、密码或业务。

升级前保存配置及完整备份，先在独立卷验证。只追加新的迁移，不修改已执行V1／V2，不通过删表或删卷处理失败。查看受控日志定位错误，切换到可信版本前确认备份和迁移兼容性。

## 生产配置

公开源码仅允许个人非商业学习，商业部署须书面授权。生产使用受控密钥注入、HTTPS、COOKIE_SECURE=true、反向代理、网络隔离、最小权限、备份保留和适用监控。生产配置和凭据不进入仓库。外部数据库覆盖DATABASE_URL、DATABASE_USER、DATABASE_CATALOG、DATABASE_PASSWORD，使用适当的受信任TLS配置。Compose本地内部网络配置不等于生产外部数据库安全方案。

本机没有Java21或Maven时，可使用Docker官方Maven容器执行完整测试；Node使用README版本。没有配置AI、第三方账号、SMTP或设备协议。系统不具备现场实时控制、安全联锁、离线执行、多实例会话共享或高可用能力。

## 备份与恢复

备份必须在受控目录以0600保存完整数据库（结构、Flyway、身份、业务、证据）；备份含密码散列和未发布演出信息，不提交或上传公开仓库。通过容器内已有环境引用数据库管理密码，不在命令行直接书写密码、不打印备份正文。

使用一致性逻辑备份，mysqladmin／mysqldump需要已授权容器。独立恢复流程：

1. 记录备份来源版本、数据库与时间，停止或暂停本项目写入，保持其他容器不变。
2. 建立本项目新的Compose项目名、独立数据库卷和单独WEB_PORT，例如18129；使用对应相同版本镜像及私有配置。
3. 启动新MySQL并导入完整备份；启动后端、前端，等待三个健康。
4. 核对Flyway success、表数、各账号登录、提示本摘要、场次快照、岗位指派、执行与暂停事件。
5. 使用scripts/smoke.py --verify比对已经保存的本项目私有验收快照，恢复验证不会写入业务。
6. 只有确认备份恢复通过后，按部署方制度切换。不要覆盖原卷或删除实际业务数据。

scripts/smoke.py --allow-test-writes仅针对独立、可销毁测试数据库，生成TEST业务及随机账号；不得指向生产。页面验收后--capture保存私有当前快照，重启与恢复后--verify逐响应核对并重新登录各岗位。

## 停止与清理

docker compose -p stagecue stop保留数据。docker compose -p stagecue down删除本项目容器及网络，保留业务卷。只有经明确确认可销毁的本次测试环境才使用down --volumes。清理前核对Compose项目标签，不影响其他容器、卷、客户数据或未提交修改。
